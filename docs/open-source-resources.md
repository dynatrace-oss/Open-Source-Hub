# Open Source Resources

Whether you're new to open source, contributing to an existing project, or maintaining a Dynatrace repository, these resources can help you get started and build sustainable practices.

External resources provide general guidance. For Dynatrace-specific requirements, use the internal policies and processes linked below or contact the Open Source Program Office (OSPO).

> **Need help?** Contact the OSPO: **[Open an open source request in Slack](https://dynatrace.enterprise.slack.com/archives/CJGELHH5E)]**. _Internal only_

## New to open source?

- [Open Source Introduction — TODO Group OSPO 101](https://todogroup.org/resources/training/): Explore what open source is, its history, and why organizations use it. Start with the Open Source Introduction modules.
- [The Open Source Definition — Open Source Initiative](https://opensource.org/osd): Learn the criteria that define an open source license.
- [OSPO Easy FAQ — TODO Group](https://todogroup.org/resources/guides/open-source-program-office-ospo-easy-faq/): Learn what an OSPO does and how it supports strategy, governance, compliance, and community.

**At Dynatrace:** Learn about the OSPO, its services, and how to request support [here](https://github.com/dynatrace-oss/Open-Source-Hub#open-source-team).

## Want to contribute?

Contributions can include code, documentation, issue reports, testing, translations, and community support.

- [How to Contribute to Open Source — Open Source Guides](https://opensource.guide/how-to-contribute/): Find a project, understand its community, and make a contribution.
- [Participating in Open Source Communities — TODO Group](https://todogroup.org/resources/guides/): Find this guide in the OSPO guide collection for advice on engaging with open source communities.
- [Building Welcoming Communities — Open Source Guides](https://opensource.guide/building-community/): Learn how to make participation welcoming and productive.

**At Dynatrace:** Before contributing on behalf of Dynatrace, review the applicable contribution guidance and approval process: **[Contribution guidance and approval links](https://github.com/dynatrace-oss/Open-Source-Hub/blob/main/docs/contributing/employee-contributions.md)]**.

## Starting or maintaining a project?

- [Starting an Open Source Project — Open Source Guides](https://opensource.guide/starting-a-project/): Consider the responsibilities involved in launching and maintaining a project.
- [TODO Group Guides and Resources](https://todogroup.org/resources/guides/): Explore *Starting an Open Source Project*, *Building an Inclusive Open Source Community*, and *Building leadership in an open source community*.
- [The Maintainer's Toolkit — CNCF Contributors](https://contribute.cncf.io/resources/videos/2021/maintainer-toolkit): Discover resources for governance, contributor pathways, security disclosures, and community management.

**At Dynatrace:** Use the repository creation process and baseline requirements when preparing a project: **[[repository creation request](https://dynatrace.enterprise.slack.com/archives/CJGELHH5E), [checklist](https://github.com/dynatrace-oss/Open-Source-Hub/blob/main/docs/publishing/publishing-checklist.md), and [baseline requirements](https://github.com/dynatrace-oss/Open-Source-Hub/blob/main/docs/publishing/new-repositories.md)]**. The baseline includes files such as README, LICENSE, SECURITY, and CODEOWNERS; check the current guidance for the full list and applicable requirements.

## Security and licensing

- [OpenSSF Scorecard](https://scorecard.dev/): Learn about automated checks that help identify software supply chain security risks.
- [OpenSSF Security Guides](https://openssf.org/resources/guides/): Explore guidance on secure development and vulnerability disclosure.
- [REUSE Tutorial](https://reuse.software/tutorial/): Learn how to document copyright and license information in a repository.

**At Dynatrace:** Follow the relevant internal security and licensing guidance and contact Security or Legal when needed: **[[Security Guidance](https://github.com/dynatrace-oss/Open-Source-Hub/blob/d594f21c2f3c729f14abec89489f9f33c74619e6/docs/maintaining/security-readiness.md), [Scorecard instructions](https://github.com/dynatrace-oss/Open-Source-Hub/blob/d594f21c2f3c729f14abec89489f9f33c74619e6/docs/maintaining/openssf-scorecard.md), [[Licensing Guidance](https://github.com/dynatrace-oss/Open-Source-Hub/blob/main/docs/governance/licensing-guidance.md)]**.

## Project health and lifecycle

- [Starter Project Health Metrics Model — CHAOSS](https://www.chaoss.community/kb/metrics-model-starter-project-health/): Explore a starting set of measures for understanding project health. Interpret metrics in the context of each project's goals and community.
- [Measuring Your Open Source Program's Success — TODO Group](https://todogroup.org/resources/guides/): Find this guide in the collection for ideas on measuring program outcomes.
- [Shutting Down an Open Source Project — TODO Group](https://todogroup.org/resources/guides/): Find this guide in the collection for considerations when a project reaches end of life.

**At Dynatrace:** Use the project health dashboard and lifecycle guidance to review ownership and plan appropriate next steps: **[[Ownership policy](https://github.com/dynatrace-oss/Open-Source-Hub/blob/main/docs/governance/maintainer-succession.md), and [archive checklist](https://github.com/dynatrace-oss/Open-Source-Hub/blob/main/docs/retiring/archive-checklist.md) or [deletion policy]([url](https://github.com/dynatrace-oss/Open-Source-Hub/blob/main/docs/retiring/deletion-policy.md)) links]**.
