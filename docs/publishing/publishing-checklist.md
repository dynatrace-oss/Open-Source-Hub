# Publishing Checklist

Use this checklist before making a repository publicly accessible.

## Purpose and ownership

- [ ] Repository purpose is documented.
- [ ] Intended audience is identified.
- [ ] Owning team is identified.
- [ ] Primary maintainer is identified.
- [ ] Backup maintainer or succession path exists.
- [ ] Support classification has been selected.
- [ ] Repository organization/location is appropriate.

## Legal and licensing

- [ ] Approved open source license is included.
- [ ] Third-party dependencies have been reviewed.
- [ ] Third-party assets may be redistributed.
- [ ] Required copyright notices and attribution are present.
- [ ] Dynatrace has the right to publish the repository content.

## Repository history

- [ ] Full Git history has been reviewed.
- [ ] No secrets or credentials are present.
- [ ] No customer information is present.
- [ ] No inappropriate personal information is present.
- [ ] No internal-only infrastructure information requiring removal remains.
- [ ] Historical secrets have been appropriately remediated.

## Documentation

- [ ] README.md is complete.
- [ ] Project status is documented.
- [ ] Support model is documented.
- [ ] Getting-started instructions exist.
- [ ] CONTRIBUTING.md exists where contributions are accepted.
- [ ] CODE_OF_CONDUCT.md exists where appropriate.
- [ ] LICENSE exists.
- [ ] Known limitations are documented where appropriate.

## Governance

- [ ] CODEOWNERS is configured.
- [ ] Repository permissions follow least privilege.
- [ ] Appropriate branch protections or rulesets are enabled.
- [ ] Issue handling expectations are defined.
- [ ] Pull request expectations are defined.
- [ ] Release responsibilities are understood.

## Security and automation

- [ ] Repository secret scanning has been reviewed.
- [ ] GitHub Actions token permissions follow least privilege.
- [ ] Third-party GitHub Actions are appropriately controlled.
- [ ] Dependency update automation is enabled where appropriate.
- [ ] Build and test automation exists where appropriate.
- [ ] Security scanning is configured where appropriate.
- [ ] OpenSSF Scorecard findings have been reviewed where applicable.
- [ ] Repository-specific `SECURITY.md` has been added if additional guidance is required.


## Public presentation

- [ ] Repository name is appropriate for public use.
- [ ] Repository description is complete.
- [ ] Relevant topics are configured.
- [ ] Documentation links are valid.
- [ ] Support information is easy to find.
- [ ] Required communication has been prepared.

## Final review

- [ ] Owning team approves publication.
- [ ] Required open source governance review is complete.
- [ ] All blocking issues have been resolved.
- [ ] Repository is ready to become public.
