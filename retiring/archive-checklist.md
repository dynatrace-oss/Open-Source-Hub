# Archive Checklist

## Decision

- [ ] Owning team has been identified.
- [ ] Owning team agrees active development has ended.
- [ ] Reason for archival is documented.
- [ ] Known users and dependencies have been reviewed.
- [ ] Replacement or successor has been identified where applicable.
- [ ] Archival is preferable to deletion.

## Issues and contributions

- [ ] Open issues have been reviewed.
- [ ] Open pull requests have been reviewed.
- [ ] Important unresolved work has been migrated where necessary.
- [ ] Contributors have been notified where appropriate.

## Documentation

- [ ] README contains an archive notice.
- [ ] Replacement project is linked where applicable.
- [ ] Migration guidance exists where appropriate.
- [ ] Repository description reflects its status.
- [ ] External documentation has been updated.

## Releases and packages

- [ ] Existing releases have been reviewed.
- [ ] Package distribution has been reviewed.
- [ ] Release automation has been disabled where appropriate.
- [ ] Consumers know whether existing packages remain available.

## Security and infrastructure

- [ ] Repository secrets have been reviewed.
- [ ] Unnecessary secrets have been removed.
- [ ] Webhooks have been reviewed.
- [ ] GitHub Apps have been reviewed.
- [ ] Unnecessary workflows have been disabled.
- [ ] External integrations have been reviewed.

## Governance

- [ ] Repository inventory has been updated.
- [ ] Lifecycle status is recorded as archived.
- [ ] Archive date is recorded.
- [ ] Final maintainer/owner information has been recorded.

## Final action

- [ ] Final repository changes are complete.
- [ ] GitHub archive feature has been enabled.
