# Contributing to the Dynatrace Open Source Hub

Contributions that improve the clarity, usability, accuracy, or consistency of Dynatrace open source guidance are welcome.

## Before contributing

Please:

1. Search existing issues and pull requests.
2. Keep changes focused.
3. Avoid adding internal-only processes, systems, contact information, or confidential material.
4. Consider whether the guidance applies broadly enough to belong in the public Open Source Hub.

## Proposing significant changes

For changes that materially alter:

- Repository governance.
- Support definitions.
- Security requirements.
- Licensing expectations.
- Publication requirements.
- Archive or deletion standards.

Open an issue before submitting a large pull request.

## Pull requests

Pull requests should:

- Explain the reason for the change.
- Update related documentation where necessary.
- Use clear, audience-neutral language.
- Avoid references that require internal Dynatrace access unless clearly identified as internal-only.

## Questions

Use GitHub Issues for questions about the guidance in this repository.

Do not use GitHub Issues to report security vulnerabilities.
